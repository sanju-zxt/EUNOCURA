# EUNOCURA — what each screen actually does

Status legend:

| Mark | Meaning |
|---|---|
| **Wired** | the screen reads and writes real routes; loading, error-with-retry and empty states are all present |
| **Degrades** | wired, but an optional dependency can be missing; the UI says which one instead of failing |
| **Preview** | sample content behind an amber "Interactive preview · fixture data" banner. Exactly one screen is in this state |

Every row below was checked against the code, not against a design document. If a
claim is not in this table, it is not implemented — video consult, e-signing,
lab-order integration, SMS/email reminders, wearables and population analytics are
all absent, and no screen offers them.

---

## Doctor portal

| Screen | Status | What is real |
|---|---|---|
| Dashboard | Wired | Visit counts, today's schedule and recent activity come from `/appointments/` scoped to the signed-in doctor |
| Patients | Wired | `/patients/` search + `/patients/{id}`. Opening a patient renders the clinical panel (prescriptions, lab results) and the visit history |
| Clinical panel | Wired | `GET/POST /prescriptions/*`, `GET/POST /lab-results/*`. Writes then post an in-app notification to the patient; a failed notification is shown as a warning and never rolls back the clinical write |
| Consultation session | Wired | Live visit read from the appointment; recording, document upload and the diagnosis request hit their own routes |
| Recording → text | Degrades | local `faster-whisper`; without it the session stays usable in text-only mode and the endpoint returns the install hint |
| Grounded chat over records / a PDF | Degrades | `POST /doctors/chat`, `/doctors/upload-pdf`; needs the local model. Answers carry quote + page; the page is checked by `services/citations.py` |
| Diagnosis draft | Degrades | `POST /appointments/{id}/diagnosis` — a *draft* the doctor must accept, labelled as model-generated everywhere it is shown |
| Citations + evidence boxes | Wired | `POST /citations/check`, `/audit`; `services/bbox.py` builds the exact word-rect overlay. Works with **no model at all** |
| New appointment | Wired | `POST /appointments/` (doctor-only), status transitions via `PATCH` |

## Patient portal

| Screen | Status | What is real |
|---|---|---|
| Dashboard | Wired | Identity from `/auth/me`, next appointment, completed visits and unread notifications from their own rows |
| Book an appointment | Wired | `GET /appointments/bookable-doctors` (real directory), `POST /appointments/self` (patient booked, id from the token), slots in the past refused server-side |
| My appointments | Wired | `GET /appointments/` scoped to the caller, `PATCH /appointments/{id}/cancel` for their own upcoming visit. Re-book links to the booking screen |
| Medications | Wired | own prescriptions; medication name / dose / frequency / instructions all come from the record |
| Lab results & trends | Wired | own results plus `/lab-results/me/series`; the normal / high / low flag is derived on the server from the reference range, never sent by the client |
| Care plan | Wired | own clinician plan. With no plan on file the screen says so — it does not invent one |
| Notifications | Wired | own inbox, unread count, mark read / read-all / delete |
| Health chatbot | Degrades | local SLM, 12 Indic languages, optional local TTS. Refuses to diagnose; emergency wording in the system prompt |
| Diet plan | **Preview** | when the patient has **no** clinician plan, the generic heart-healthy preview from `src/data/previewDietPlan.js` renders behind the amber banner plus a line saying none of it is real. The banner disappears the moment a plan exists |

## Security and privacy — as implemented

* Argon2 password hashing; JWT bearer tokens, 7-day expiry.
* The password hash is **server-owned**: a signup never sends one, and the value is
  overwritten by the hash of the plain password.
* Every appointment / prescription / lab-result / care-plan / notification read is
  **scoped to the caller**. A stranger asking for someone else's record gets `404`,
  not `403`, because a `403` confirms that the id exists.
* `GET /doctors/` and `GET /patients/` are projected: no `hashed_password` field leaves
  the server.
* Secrets come from the environment only; `.env` is gitignored and CI proves it stays
  untracked. No patient data is in the repository, and demo data is generated by
  `backend/tools/seed_all.py`.

### Not implemented — do not claim

End-to-end encryption, HIPAA or any other certification or audit, immutable audit
logs (the citation audit trail is append-style but not tamper-proof), per-field access
trails, anonymisation pipelines, data-export or delete-account endpoints.

## Engineering

| Concern | State |
|---|---|
| Tests | 7 offline suites + a 27-check live route smoke test; `backend/scripts/ci_checks.py` runs the whole gate in ~8 s |
| CI | `.github/workflows/ci.yml` — backend gate on every push, frontend production build, optional docker job (dispatch only) |
| Boot | 0.7 s. Optional heavy stacks (FAISS/torch, faster-whisper, boto3) are imported on first use, not on import |
| Frontend bundle | route-level `React.lazy`; entry chunk 65 kB gzip. PDF/export libraries are dynamically imported |
| Failure model | every optional dependency degrades with a readable reason in `/healthz` and in the UI; nothing silently half-works |

## Deliberately not measured

No time-saved, accuracy-delta or cost figure is claimed anywhere. What *is* measured
on every document is how many offered claims survived verification and how often the
cited page had to be corrected — that comes out of `citations.CitationReport` and is
printed in the UI.

---

EUNOCURA is a document-intelligence harness with two portals on top, not a certified
clinical system. The parts that decide what a doctor sees are deterministic, tested and
small enough to read in one sitting — which is the actual claim.
